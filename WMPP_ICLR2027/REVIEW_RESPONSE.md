Author's decision: critique accepted as valid, but (a) the chunk-level diagnostic would over-complicate the paper -> run only if a rebuttal needs it; (b) main text NOT rewritten (over-defensive). Diagnostic design (ready to launch, ~1 day code + 9 CPU jobs of 1-2 h):
- Datasets scene-play, puzzle-3x3-play, cube-triple-noisy; 3 bank seeds; states from WMPA's own rollouts at the reported cell, stratified early/mid/late (~150 states per dataset).
- Branch protocol: at state x, for every candidate i run i for c steps in the real simulator, then the reference policy b (the seed's best fixed policy; optional second run with b = incumbent) to episode end. Environments are deterministic, so one branch gives Q^{b,c}(x,i) exactly.
- Three rankings per state: learned-model score S_i (WM rollout + value, as deployed), true-dynamics score (same value head on the real c-step branch states, SimRolloutRanker), real chunk outcome Q^{b,c}.
- Metrics on discordant states only (report their fraction = local-headroom diagnostic replacing U - B_max): best-candidate selection rate with chance baseline, selection regret (max_i Q - Q(chosen), success points), pairwise ranking accuracy; per phase.
- Reading: true-dynamics ranking good but learned ranking poor -> model error reorders candidates; true-dynamics ranking poor -> scorer misaligned with outcome even under correct dynamics (App. I "model error versus score-outcome mismatch").
- Reuse: scripts/collect_oracle.py + evaluation/oracle.py (real-simulator branches from decision states; WMPA/best/Random generators), planners/sim_rollout.py::SimRolloutRanker (true-dynamics score), scripts/report_diagnostics.py (pairwise accuracy, top-1). To add: branch mode "candidate c steps then continuation policy", phase-stratified sampling, per-state WM score logging, regret metric.
- Expected: scene-play learned ~ true-dynamics ranking (true-sim WMPA is within +2), residual regret from the scorer; puzzle-3x3-play low regret (direct value, 100%); cube-triple-noisy few discordant states (local alternatives scarce).

Self-trained direct value head (2026-09-19). Reviewer-facing point: on the puzzle family the direct scorer is the state-value network of the bank's GCIQL member, so the arbiter borrows a component from a policy it is supposed to treat as a black box. Fix implemented and verified, deferred to the rebuttal by the author's decision (not urgent, and the paper's numbers do not change).
  What exists: world_model/model.py grows an optional direct (IQL) head, config direct_head=True, trained JOINTLY with the dynamics and the metric head by exactly GCIQL's objective (expectile regression of V toward min_j target Q_j; one-step Q targets bootstrapped through V; direct_discount / direct_expectile / direct_tau). Off by default, so every existing checkpoint rebuilds unchanged. eval_planner --critic_scorer=wm scores with it and runs Q-select from its twin critic. Test: tests/test_world_model.py::test_direct_value_head.
  Evidence (puzzle-4x5-play, 1M steps, run wm-directhead/sd000_s_60482686, evaluated on 3 bank seeds at the reported cell): self-trained 18.1 +- 3.5 vs borrowed 18.3 +- 3.5, paired -0.1 [-1, +1]; metric head 10.1; Best policy 14.1. Its own twin-Q Q-select reproduces GCIQL's (c=1 19.9 vs 19.6, c=10 11.3). Training log healthy: value/critic loss 0.071/0.552 (val 0.056/1.100), metric-head validation rank corr 0.884, i.e. unchanged from the original model.
